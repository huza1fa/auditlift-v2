# Incident Response Policy

**Company:** {{companyName}}
**Team Size:** {{teamSize}}
**Date:** {{date}}

## 1. Purpose

This Incident Response Policy establishes a systematic approach for {{companyName}} to prepare for, detect, contain, and recover from security incidents.

## 2. Incident Classification

| Severity | Description                                   | Response Time        |
| -------- | --------------------------------------------- | -------------------- |
| Critical | Data breach, ransomware, system compromise    | Immediate (< 1 hour) |
| High     | Unauthorized access attempt, malware detected | < 4 hours            |
| Medium   | Policy violation, suspicious activity         | < 24 hours           |
| Low      | Minor issues, informational alerts            | < 72 hours           |

## 3. Response Procedures

### 3.1 Detection & Reporting

All {{companyName}} team members must report suspected incidents immediately. Reports go to the designated security contact.

### 3.2 Containment

- Isolate affected systems
- Preserve evidence for forensic analysis
- Notify affected stakeholders

### 3.3 Eradication & Recovery

- Remove malicious content or unauthorized access
- Restore systems from known-good backups
- Verify system integrity before returning to production

### 3.4 Post-Incident Review

A post-incident review is conducted within 5 business days to identify root cause and prevent recurrence.

## 4. Communication

- Internal: Notify team members within 2 hours of a High/Critical incident
- Customers: Notify affected customers within 72 hours of a data breach
- Regulators: Notify as required by applicable regulations

## 5. Testing

Incident response procedures are tested annually via tabletop exercises.
